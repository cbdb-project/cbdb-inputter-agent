## What this case taught the repo

Most of a `TEXT_CODES` row can only be changed through the `text-entity` aggregate,
which this client did not model. It is now modelled, update only
(`src/cbdb_agent/text_entity_aggregate.py`, `docs/04-field-whitelists.md` §20). The
trap that shaped it: upstream treats an absent `instances` key as an empty list, so an
update that does not mention edition rows deletes them all. Logged in
`docs/02-review-log.md`, *"text-entity aggregate (update only) — 2026-11-18"*.
